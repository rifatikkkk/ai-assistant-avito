# **Тестовое задание на стажёр-Frontend**

## **Документация по серверной части**

При выполнении тестового задания использовал ваш API для работы с серверной частью.

### **Установка и запуск**

1. Выполните клонирование серверной части, выполнив `git clone https://github.com/rifatikkkk/server-side-avito`
2. Перейдите в папку `server`, выполнив `cd server-side-avito/server`
3. Установите зависимости, выполнив `npm install`
4. Запустите серверную часть - `npm run start`
   После этого серверная часть будет запущена на порту 8080

**Комментарий**: вы можете не клонировать мою версию API, в этом случае вам нужно будет добавить в ответ поле `id` во получения объявлений (/items) для последующей работы со списком и карточкой объявления. Также были изменены ссылки на подгружаемые пакеты из npm-регистра.

```

      // остальной код

        id: item.id, // Добавлен атрибут id
        category: item.category,
        title: item.title,
        // остальной код...
       }))
    // остальной код ...
```

## **Документация по интеграции LLM**

При выполнении тестового задания использовал локальную программную платформу Ollama.

### **Установка и запуска**

1. Установите [Ollama](https://ollama.com/download)
2. Загрузите модель, с которой будете работать. В своем решении использовал модель `phi3:mini`

   ```bash
   ollama pull phi3:mini
   ```

3. Убедитесь, что Ollama запущена:

   ```bash
   ollama serve
   ```

4. Доступ к Ollama возможен напрямую с помощью REST API:

   ```
   POST http://localhost:11434/api/generate
   ```

## **Документация по клиентской части**

### **Установка и запуск**

1. Выполните клонирование клиентской части, выполнив `git clone https://github.com/rifatikkkk/ai-assistant-avito`
2. Перейдите в папку `ai-assistant-avito`, выполнив `cd ai-assistant-avito`
3. Установите зависимости, выполнив `npm install`
4. Создайте файл `.env` в папке `server`. Заполните файл следующими ключами и их значениями:

   ```
   VITE_API_URL=http://localhost:8080
   ```

   **Важно**: ключ `VITE_API_URL` в файле `.env` должен содержать URL адрес серверной части, по которому выполняется взаимодействие

   ```
   VITE_OLLAMA_MODEL=phi3:mini
   ```

   **Важно**: ключ `VITE_OLLAMA_MODEL` в файле `.env` должен содержать название модели. Например, модель `phi3:mini`

5. Запустите клиентскую часть - `npm run dev`

После этого клиентская часть будет запущен на порту 3000.

## **Принятые решения**

### **Общие решения**

1. В данном решение отсутствует использование UI-библиотеки - все было сверстано вручную. Принято решения для уменьшения размера bundle и контролем над компонентами, но требует больше времени на разработку;
2. При проектировании придерживался методологии FSD для повышения масштабируемости и переиспользованности компонентов;
3. Верстка предусматривается для экранов шириной `1400px`.

### **Страница списка объявлений**

1. Поиск элементов происходит по нажатию клавиши `Enter` или кнопке/иконке `Поиск`;
2. Сортировка цены происходит на клиентской стороне: были внесены минимальные изменения в серверную часть - отсутсвует сортировка по атрибуту `price`;
3. Все остальные сортировки и фильтры связаны с отправкой запроса на серверную часть;
4. Бэйдж `Требует доработок` приклеен к нижней части карточки, по отношению к высоте соседних элементов;
5. В общем запросе на получение объявлений указывается параметр `limit=100` для получения всех значений (в `seed.ts` 32 элемента). Без указания данного параметра, количество объявлений составляет 10;
6. Пагинация осуществлена на клиентской стороне.

### **Страница карточки объявления**

1. Ширина блока `Описание` не превышает ширину картинки (как было в дизайне), хотя в указанных примерах блок был на всю ширину;

### **Страница редактирования объявления**

1. Поля заполнения сохраняются в localStorage, тем самым позволяя сохранить данные при перезагрузке;
2. По кнопке `Отменить` удаляются сохраненные изменения в localStorage;
3. После заполнения полей, по кнопке `Сохранить` осуществляется переход на главную страницу спустя 5 секунд;
4. Отправка запросов к модели LLM осуществляется при помощи библиотеки `ollama` на локальную программную платформу;
5. При отправке повторных запросов к модели LLM повышается риск получения некорректных ответов (подозреваю, что дело в модели или промпте);
6. Параллельная отправка запросов к модели и редактирование полей без прерывания.
